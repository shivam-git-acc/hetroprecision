The attention kernel itself already reads KV at ~1.26 TB/s. The waste is cache management. A pre-allocated cache adds a mask, which drops FlashAttention for a kernel that cannot share KV heads.

Source: results/nsys/decode_c32768_b8*, decode_static_c32768_b8* · shares of GPU kernel time per decode step

Measure first: we expected attention to dominate. Instead HuggingFace spends 49 percent of each step copying the whole cache to append one token. The obvious fix, a static cache, made it 5.6 times slower because the mask forced a fallback kernel that expands 4 KV heads into 28. So the right baseline is a paged, pre-allocated cache read directly by a kernel with native grouped-query attention, which is what vLLM and our planned kernel do.
