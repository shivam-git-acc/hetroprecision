Problem

Every new token reads the whole KV cache

Bytes read per decode step, Qwen2.5-7B, BF16, 32K context

Batch 1 · 17.2 GB

Batch 8 · 30.3 GB

Weights 15.3 GB, shared by the batch

KV cache, 56 KB per token per sequence

At 32K × batch 8 the KV cache (15.1 GB) is as large as the weights. Decode is limited by memory bandwidth, so bytes read set the speed.

Our question

Is giving each KV head its own bit-width free at inference time?

Papers allocate bits per head and report quality. We measure what it costs in a real kernel: dispatch, imbalance, unpacking.

KV per token = 2 × 28 layers × 4 KV heads × 128 dims × 2 bytes. Weight size measured on GPU.

Qwen2.5-7B uses 56 KB of KV cache per token. At 32K context and batch 8 that is 15 GB, the same as all the model weights, and every decode step must read all of it. Reducing those bytes is what quantization is for. The papers say mixed precision per head is free; we want to measure whether it is.
